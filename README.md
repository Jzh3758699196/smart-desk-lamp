# 智能光控台灯 · 照度闭环控制（STM32）

按「设定照度」而不是「挑亮度档位」工作的台灯：手机给出目标照度，STM32 读取 BH1750 的照度值，  
用 PWM 经 MOS 管调节 24V LED 灯板，反复逼近，直到桌面照度收敛到设定值附近。

| 项目   | 说明                                                         |
| ---- | ---------------------------------------------------------- |
| 状态   | 可稳定运行（工程可编译、已烧录验证）                                         |
| 主控   | STM32F103C8T6（Cortex-M3，64KB Flash / 20KB SRAM，外部晶振 12MHz） |
| 开发环境 | Keil MDK5（ARM Compiler 5，ARMCC V5.06）＋ STM32F10x 标准外设库     |
| 语言   | C                                                          |
| 感知   | BH1750 数字照度传感器（硬件 I2C1，100kHz）                             |
| 调光   | TIM2_CH2 PWM（1kHz）→ MOS 管栅极 → 24V LED 灯板                   |
| 交互   | HC-05 蓝牙模块（USART1，38400 8N1）                               |

| 时间   | 2026 年                                                     |

## 为什么做这个

现有台灯只有固定档位，调光时不参考环境光：同样一档，白天开着顶灯和深夜关着顶灯，  
桌面实际照度差别很大，眼睛要反复适应。

或者我把控制目标改了一句话：**从「选一个亮度档位」变成「设定我要多少照度」**，  
让灯自己把差额补上。它本质上是一套照度闭环：测量 → 求偏差 → 调整 → 再测量。

**适用场景**：宿舍书桌、自习位这类环境光会变化的桌面——使用者只需要给出一个目标照度值，  
不用关心此刻该拧到哪一档。

## 工作原理

```
手机端输入目标照度（如 L500@）
        │  蓝牙透传（HC-05，USART1，38400 8N1）
        ▼
   STM32 接收并解析设定值
        │
        ├── BH1750 采样当前照度（I2C1，连续高分辨率模式）
        │
        ▼
   偏差 = 目标照度 − 实测照度
        │
        ▼
   逐步调整 PWM 占空比（TIM2_CH2 → MOS 管栅极）
        │
        ▼
   24V LED 灯板亮度变化 ──► 回到 BH1750 采样（循环，直至偏差落入死区）
```

## 蓝牙控制协议

每条指令以 `@` 作为一帧的结束符，在 USART1 接收中断里判断收帧完毕。

| 手机发送                 | 含义                              |
| -------------------- | ------------------------------- |
| `0` – `100`          | **手动模式**：直接设定 PWM 占空比（%），同时退出闭环 |
| `ON`                 | **手动模式**：全亮（占空比 100%）           |
| `OFF`                | **手动模式**：熄灭（占空比 0）              |
| `L<照度数值>`，范围 1–20000 | **闭环模式**：设定目标照度，灯自动逼近该值         |

手动模式用于调试与固定亮度，闭环模式是这套台灯的主要用法。  
接收缓冲 16 字节，`@` 之前的字符被视为有效载荷。

## 闭环控制参数

| 参数   | 取值               | 说明               |
| ---- | ---------------- | ---------------- |
| 采样节奏 | 主循环计满 20 万次采一次   |                  |
| 上调条件 | 实测 < 目标 − 20 lux | 占空比 +1%（上限 100%） |
| 下调条件 | 实测 > 目标 + 20 lux | 占空比 −1%（下限 0%）   |
| 死区   | `目标 ± 20 lux`    | 落在此区间内不动作，避免反复抖动 |

采用：逐步逼近 + 死区，而不是一次算到位，是因为实际光路不是线性的：灯具输出、  
传感器位置、桌面反射都会影响最终读数，逐步试探比套公式可靠。

## 设计取舍

做之前定下的几件事，以及为什么这么定：

| 取舍    | 选择                               | 理由                                                                                              |
| ----- | -------------------------------- | ----------------------------------------------------------------------------------------------- |
| 控制目标  | 把「调亮度」变成「照度的闭环控制」                | 只有闭环才能自动跟上环境光的变化，开环调档做不到                                                                        |
| 传感器   | BH1750（而非光敏电阻）                   | I2C **数字输出、直接给出 lux 值**，省去自己标定光强的麻烦                                                             |
| 驱动方式  | MOS 管（IRLZ24N）+ PWM（而非 MCU 引脚直驱） | 24V 灯板约 1A 的电流**远超 MCU 引脚的驱动能力**，必须由 MOS 管做开关；选逻辑电平管是因为它的栅极阈值只有 1~2V，**3.3V 引脚可直接驱动，不必再加一级三极管** |
| 交互方式  | 手机经 HC-05 蓝牙（而非板载按键）             | 目标照度需要经常修改，手机输入比按键直观                                                                            |
| 设定值定义 | **桌面总照度**（环境光 + 台灯光的叠加值）         | 控制目标直观，不用去估计环境光本身有多少；代价是环境光剧烈变化时，灯的输出要跟着摆动                                                      |

## 实现过程

按「先让东西动起来，再一层层加能力」的顺序推进，每一步都能独立验证：

| 阶段      | 内容                         | 怎么验证                    |
| ------- | -------------------------- | ----------------------- |
| 1. 驱动点亮 | GPIO 配合 MOS 管，让 24V 灯板受控点亮 | 置高置低看通断，量 MOS 栅极电压      |
| 2. 调光   | 定时器输出 PWM（TIM2_CH2 / PA1）  | 改占空比，看亮度是否随占空比连续变化      |
| 3. 感知   | 接通 BH1750（硬件 I2C1）         | 遮挡、开灯关灯，看读数是否在合理区间内单调变化 |
| 4. 闭环   | 加入偏差比较与调节逻辑                | 人为改变环境光，看照度能否收敛且不来回振荡   |
| 5. 通信   | 接入 HC-05，手机下发目标照度          | 手机改数值，灯的输出立刻跟着变         |
| 6. 联调   | 整机跑通，处理边界情况                |                         |

这样拆的目的是：任何一步出问题都能定位在这一步里，而不用在一个整体里猜。

## 怎么运行

1. 用 Keil MDK5（ARM Compiler 5）打开工程 `1.uvprojx`，编译
2. 用 **ST-Link** 经 SWD 接口（SWDIO / SWCLK）烧录到板子
3. 给 24V 灯板供电
4. 手机使用微信小程序蓝牙串口助手，连接 HC-05
5. 发送 `L500@` 进入闭环，观察灯的输出是否随之改变；发送 `50@` 可切回手动模式

## 开发过程中踩的坑

### 蓝牙连上了，但一直收不到数据

**现象**：手机与 HC-05 能连接成功，但 STM32 端始终收不到手机发来的数据。

**排查过程**：

1. 换另一部手机复现 —— 现象一致，先排除手机端的问题；
2. 核对模块供电与串口交叉接线 —— 均正常；
3. 回到模块本身查资料 —— HC-05 的出厂波特率可能不是常见的 `9600`，而是 `38400`。

**原因**：代码里 USART 按 9600 初始化，与模块实际波特率不匹配，  
两端帧格式对不上，数据根本没有被正确接收。

**解决**：把 STM32 端的串口配置改成 38400，通信立刻恢复正常。

**收获**：此后遇到串口不通，我会先对齐两端的波特率、数据位、校验位，再回头怀疑上层逻辑。

## 已知不足与改进方向

这些是我在做完之后回头看时发现的问题，记录在此：

- 发光点过少，也过于集中，导致光照强度在空间上变化剧烈
- 光强检测点少（只有一个）导致不可靠，可能受到偶然环境因素影响
- 死区宽度 20 lux 目前是写死的：可以做成宏或变量，方便按不同灯板调整；
